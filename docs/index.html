Goal

Refinement algorithms (Kernighan–Lin in Lab 04, Fiduccia–Mattheyses in Lab 05) only improve a split. They need a legal starting split first. Build three kinds of start, report cutsize and balance for each, and see how much the start changes the answer.

Definitions

  • Split: every node on exactly one of two sides, called "0" and "1". AB|CDE means A, B on one side and C, D, E on the other. Swapping the labels gives the same split.
  • Cutsize: total weight of the edges whose two ends are on different sides.
  • Balance: side sizes. Here every node has size 1, so sizes are node counts. ratio = smaller side / larger side, imbalance = |difference| / total (both from common/graphutil.py balance_metrics).
  • Legal start: both sides non-empty and neither side larger than ceil(n / 2). For 5 nodes the sides may be 2|3 (not 1|4, not 0|5). For 6 nodes only 3|3 is legal.
  • cap = ceil(n / 2) nodes per side. half = floor(n / 2) nodes.

Why the cap: putting every node on one side gives cutsize 0, which looks perfect and is useless. A cut is only worth comparing between legal splits.

API (what --impl looks for)

nodes is a list of names, edges is a list of (u, v, w) tuples with u < v. Each function returns {node: "0" | "1"}. Your functions may receive the nodes and edges in any order; the answer must not depend on it.

random_bipartition(nodes, seed)        # seeded shuffle, deal half
greedy_bipartition(nodes, edges)       # anchor on the heaviest edge
grow_bipartition(nodes, edges, start)  # flood outward from one node
is_legal(nodes, assignment)            # True when the split is legal

You may copy mulberry32 from the checker. Python's random and JavaScript's Math.random never agree, so the checker and the browser lab share this one small generator.

Pseudocode

Random start

random(seed):
  order = nodes sorted by name
  rng = mulberry32(seed); throw away its first two numbers
  for i = n-1 down to 1:
      j = floor(rng() * (i + 1))
      swap order[i], order[j]
  side 0 = first floor(n/2) nodes of order, side 1 = the rest

Why throw away two numbers: the first outputs of small seeds look alike. Without it, seeds 0, 1, 2, 3 would all give the same split on the tiny graph.

Greedy start (exact rule)

greedy:
  cap = ceil(n/2)
  1. anchor = the heaviest edge. Tie: smaller (u, v). Both ends go to side 0.
  2. seed of side 1 = the unplaced node with the smallest total weight to the placed nodes.
     Tie: smaller name. It goes to side 1.
  3. while nodes remain:
       x = the unplaced node with the largest total weight to the placed nodes. Tie: smaller name.
       cost0 = weight from x to side 1     (cut added if x joins side 0)
       cost1 = weight from x to side 0     (cut added if x joins side 1)
       only a side with fewer than cap nodes may be chosen
       put x on the cheaper allowed side; equal cost: side 0

Grow start (exact rule)

grow(start):
  half = floor(n/2)
  grown = [start]
  while len(grown) < half:
      add the node outside grown that is reached by the heaviest single edge leaving grown
      Tie: smaller name. If no edge leaves, add the smallest unplaced name.
  side 0 = grown, side 1 = the rest

Try several starts

best_start: build random(seed) for a few seeds, greedy, and grow(x) for every node x.
Throw away illegal ones, keep the smallest cutsize. Tie: the first one built.

Extra graph 1: star_graph.json — the size cap

A–B 9, and A to each of C, D, E, F with weight 5. Six nodes, so only 3|3 is legal. Total weight 29.

Start Split Sizes Cut Legal?
greedy (with cap) ABD|CEF 3|3 15 yes
OLD greedy (no cap) ABDEF|C 5|1 5 no

Why: the old rule keeps putting nodes next to A, because that adds no cut. The cut looks 3 times better but one side holds five of six nodes. A cut of 5 does not beat a cut of 15 when the 5 is not a legal start. (The lowest cut any 3|3 split can have is 15, so the capped greedy is optimal here.)

Extra graph 2: tie_graph.json — a tie decides the answer

A–B 5, A–E 3, B–F 3, C–D 1, D–E 5, E–F 1. Both A–B and D–E weigh 5.

Anchor Split Cut
A–B (smaller name, the rule) ABE|CDF 9

Reversing the order of the nodes and edges you pass in must not change the result: the rule says "smaller (u, v)", not "first in the list". Grow from C or from F also finds ABF|CDE, cut 4. Best of greedy and the six grows: 4, from grow C.

Extra graph 3: bridge_graph.json — the heaviest wire is not always inside

Two triangles A–B–C and D–E–F, every triangle edge 3, joined by the bridge C–D with weight 4. Total weight 22.

Start Split Cut
greedy AEF|BCD 12
grow A or B ABC|DEF 4
grow C or D ACD|BEF 12
grow E ABF|CDE 12
grow F ABE|CDF 12

Why: the heaviest edge is the bridge, so greedy anchors on C–D and starts with one node from each triangle on the same side. Grow from C also takes D first (weight 4 beats 3), then A (a four-way tie at 3, smallest name), giving ACD. Grow from A takes B (A–B and A–C tie at 3, smaller name), then C, and keeps the triangle whole. Best of greedy and the six grows: 4, from grow A.

The old greedy, for contrast

The greedy in the shared lab code before this upgrade is written out in the checker as greedy_legacy. It is not a reference. It had no size cap, and it forced the alphabetically first leftover node (C on the tiny graph) onto side 1 without looking at any weight.

Graph OLD greedy New greedy
tiny AB|CDE, cut 5 ABC|DE, cut 3
tiny, letters renamed A↔E and B↔D AB|CDE, cut 3 cut 3
star ABDEF|C, sizes 5|1, cut 5 (not legal) ABD|CEF, sizes 3|3, cut 15

The same graph with other letters gave the old greedy another cut, so its "cut 5" depended on the names, not on the graph. The new rule only reads names to break ties.

Full narration transcript

Initial bipartition

Before a computer can improve how a chip is split, it needs a first split, called the initial bipartition. You will meet three ways to build one: random, greedy and grow. On one small graph, they give cuts from three to sixteen. The habit that fixes it: try several starts, keep the best.

From a chip to a graph

A chip is made of small building blocks called cells, joined by wires. Our example has five cells, named A to E. Some pairs share many wires, others only one.

Cells become dots, wires become lines

We draw each cell as a dot, called a node. A line between two nodes is an edge. Its number, the weight, counts the wires between the pair. A–B and D–E are the heaviest, with five wires each.

Two numbers: cut and balance

Splitting the cells into two sides is called a bipartition. Edges that cross between the two sides are cut, and drawn in red. The cutsize adds up their weights: here, two plus one makes three.

Balance: no side too big

Putting every cell on one side gives a cut of zero, but that split is useless. So we also check balance: how many cells each side holds. A split is legal when no side holds more than three of the five.

Why a starting split?

Labs four and five teach two famous methods, called KL and FM. They improve a split by moving cells from one side to the other. But KL and FM need a legal split to start from. Think of picking two teams: first any two teams, then swaps to make the game fair. A good first split leaves less swapping to do. Pause and guess: could a split made at random be as good as this one, with cut three?

Three ways to build a first split

Three short recipes can build a first split: random, greedy and grow. And yes, a random split can reach cut three, if it is lucky. Every recipe puts two cells on one side, and three on the other.

Random seed 5: lucky ABC|DE cut 3

Recipe one is random. Shuffle the five names like cards, and deal two of them to one side. A number called the seed fixes the shuffle, so the same seed always gives the same split. Seed five deals D and E together. Only C–D and C–E are cut: three.

Greedy: ABC|DE cut 3

Recipe two is greedy: at each step, it takes what looks best right now. It keeps the heaviest edge, A–B, inside one side. D, which has no wire to A or B, starts the other side. Each other cell joins the side where it cuts less. The cut is three again.

Grow from D: ABC|DE cut 3

Recipe three is grow: a side spreads from one start node, like a drop of ink on paper. Start from D. The heaviest edge leaving D goes to E, so E joins. Two cells are enough, so the side stops. A, B and C form the other side: cut three again.

All three found cut 3. Was that luck?

All three found cut three. Pause and guess: was that luck?

Worked example: an unlucky seed

A single unlucky shuffle can make the cut more than five times worse. So yes, it was partly luck. With seed three, B and D land on one side, and A, C and E on the other.

Adding up the cut

Let's add up the cut, edge by edge. A–B five, B–C four, C–D two, and D–E five. That makes sixteen.

The worst legal split

Both heavy edges are cut, so this is the worst legal split of all. Over sixteen seeds, the cut goes from three to sixteen. Only three of those seeds hit the best cut, three.

Grow depends on the start node

Grow has no luck in it, but it has a choice: the start node. Let's start from A instead of D.

Grow from A, step by step

The heaviest edge leaving A goes to B, with weight five, so B joins A. With two cells, the side is full, and it stops.

Grow from A: AB|CDE cut 5

C, D and E form the other side, so A–C and B–C are cut. One plus four makes five, which is worse than three. Starting from C is even worse: a cut of nine.

Keep the best legal start

The fix is simple: try several starts, keep the best. Build a few random seeds, greedy, and grow from every node. Drop any split that breaks the size rule, then keep the smallest cut. Here, greedy and the five grows give three, five, five, nine, three and three. So the best is three: A, B and C against D and E. Pause and guess: can a smaller cut ever be the worse choice?

Trap 1: no size limit

Three traps can fool a method that looks sensible. And yes, a smaller cut can be the worse choice. Here is a star: A in the middle, wired to five other cells. An older greedy had no size limit, so it kept adding cells next to A. It ended with five cells against one, and a cut of five.

Trap 1: the size limit fixes it

With six cells, each side must hold exactly three, so that split is not legal. Our greedy stops each side at three cells, and gets fifteen. No legal split of this star does better.

Trap 2: a tie can decide the answer

In this graph, A–B and D–E both weigh five. Greedy must pick one of them to start from. The rule picks the smaller name, A–B, and that gives a cut of nine.

Trap 2: the other anchor

Starting from D–E instead gives a cut of four. So a tie rule more than doubled the cut. Grow from C also finds four.

Trap 3: the heaviest wire is not always inside

Here are two triangles, joined by one bridge, C–D, with weight four. Every triangle edge weighs three. Greedy starts from the heaviest edge, which is the bridge itself. So C and D begin on the same side, and the cut ends at twelve.

Trap 3: grow keeps the triangles

Grow from A keeps its triangle together, and cuts only the bridge: four. Pause and guess: is grow always better than greedy?

Implement track

If you like programming, write the three recipes in Python. The examples file gives the exact rules, ties included. Run the checker once to print every correct answer. Then run it on your own file. It also feeds the graph in reverse order, so a missing tie rule shows up as a failure.

Remember

Random is fast, but it depends on luck. Greedy keeps heavy edges inside, but ties and bridges can fool it. Grow depends on its start node. Report the balance with every cut, and never let a side pass its limit. Break ties by name, not by the order of the input file. So try several starts, keep the best legal one.
